1. Restart the LoRaWAN interface (fPort 50)

{
    "fPort": 50,
    "Type": "Config",
    "Config": [
        {
            "Param": "restartLoRaWAN",
            "Value": 1
        }
    ]
}


2. Configure ADR and SF (2 parameters, fPort 50)

{
    "fPort": 50,
    "Type": "Config",
    "Config": [
        {
            "Param": "adr",
            "Value": 0
        },
        {
            "Param": "sf",
            "Value": "SF9BW125"
        }
    ]
}

- Enum values are given as a number (3) or as the label shown in uplinks ("SF9BW125").
- At most 10 parameters, and at most 64 bytes once encoded (a 15 character string takes 18).
- Strings are ASCII, at most 15 characters.


3. Read device registers (fPort 100)

{
    "fPort": 100,
    "Type": "Reading",
    "Reading": [
        "firmwareVersion",
        "adr",
        "sf",
        "radioMode",
        "numberOfJoinAttempts",
        "linkCheckTimeframe",
        "dataRetransmission",
        "lorawanWatchdogAlarm"
    ]
}

- At most 10 registers per Reading. Registers marked (W) below cannot be read.
- The answer comes as an uplink on fPort 100.


4. Configure a 15 min periodic unconfirmed uplink on fPort 2

{
    "fPort": 2,
    "Type": "Periodic",
    "Periodic": {
        "UplinkInterval": 15,
        "Mode": 0,
        "Status": 1,
        "Registers": [
            "channel1RelayStateInfo",
            "channel2RelayStateInfo",
            "channel1OnOffCycles"
        ]
    }
}

- fPort 1 to 10, one configuration per fPort. Any subset of the four fields may be sent.
- UplinkInterval: minutes, 1 to 65535
- Mode: 0 = unconfirmed uplink, 1 = confirmed uplink
- Status: 0 = fPort disabled, 1 = fPort enabled
- Registers: at most 10 readable registers


5. Switch a relay (fPort 50)

{
    "fPort": 50,
    "Type": "Config",
    "Config": [
        {
            "Param": "channel1DesiredState",
            "Value": "ON_BY_DL"
        },
        {
            "Param": "channel2DesiredState",
            "Value": "AUTO"
        }
    ]
}

- channel<N>DesiredState: AUTO (0), ON_BY_DL (1) or OFF_BY_DL (2) over LoRaWAN.


6. Momentary toggle of relay 1 for 30 s (fPort 50)

{
    "fPort": 50,
    "Type": "Config",
    "Config": [
        {
            "Param": "channel1MomentaryDuration",
            "Value": 30
        },
        {
            "Param": "channel1MomentaryRequestId",
            "Value": 7
        }
    ]
}

- Duration 1 to 120 s, sent together with a request id (0 to 255).


7. Voltage protection on relay 1 (fPort 50)

{
    "fPort": 50,
    "Type": "Config",
    "Config": [
        {
            "Param": "channel1VoltageProtection",
            "Value": "ENABLED"
        },
        {
            "Param": "channel1VoltageHighLimit",
            "Value": 253
        },
        {
            "Param": "channel1VoltageLowLimit",
            "Value": 180
        }
    ]
}

- Limits in volts, 0 to 300. The device requires the high limit to stay above the low limit
  at every write, so order the parameters accordingly (raise the high limit first).


8. Week timer of relay 1: Monday 08:00 to 17:00 (fPort 50)

{
    "fPort": 50,
    "Type": "Config",
    "Config": [
        {
            "Param": "channel1MondayWindow1StartMinute",
            "Value": 480
        },
        {
            "Param": "channel1MondayWindow1EndMinute",
            "Value": 1020
        },
        {
            "Param": "channel1WeekTimer",
            "Value": "ENABLED"
        }
    ]
}

- Minutes of the day, 0 to 1440; 4 windows per day, Monday to Sunday.


9. Prepaid budget of relay 2 and user consumption reset (fPort 50)

{
    "fPort": 50,
    "Type": "Config",
    "Config": [
        {
            "Param": "channel2Prepaid",
            "Value": "ENABLED"
        },
        {
            "Param": "channel2AllowedConsumption",
            "Value": 1000
        },
        {
            "Param": "channel2ConsumptionCurrentUser",
            "Value": 0
        }
    ]
}

- Consumption in kWh; the current user consumption can only be reset to 0.


10. LoRaWAN watchdog: relays to their initial state as soon as the network is lost (fPort 50)

{
    "fPort": 50,
    "Type": "Config",
    "Config": [
        {
            "Param": "channel1InitialState",
            "Value": "OFF"
        },
        {
            "Param": "channel2InitialState",
            "Value": "OFF"
        },
        {
            "Param": "watchdog",
            "Value": "ENABLED"
        }
    ]
}

- The initial states apply as soon as the device detects the loss of the network, without delay.
  With the watchdog DISABLED, a network loss is silent (the relays keep their control) until the
  watchdog is ENABLED during the outage, which applies the initial states at once.
- The relays keep their initial state (reason WATCHDOG) until the device joins the network again
  or the watchdog is disabled, then return to their previous control.
- lorawanWatchdogAlarm reads ALARM while the network is lost.
